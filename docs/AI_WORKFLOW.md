# ChatGPT + Codex 협업 운영 가이드

작성일: 2026-10-23 · 상태: **협업 운영 규칙 제안/문서화**. 자동 배포와 CI는 아직 미구축.

## 목적
아이폰과 PC에서 ChatGPT와 Codex를 병행하고, GitHub 저장소를 **공통 코드·진행 기록의 기준**으로 사용한다. 어느 AI가 작업해도 다른 AI가 최신 코드와 문서를 읽고 이어서 작업할 수 있게 한다.

## 책임 분담
| 상황 | 권장 도구 | 기록 위치 |
| --- | --- | --- |
| 요구사항·아키텍처·작은 로직 수정·설명·코드 리뷰 | ChatGPT | Issue/PR/문서 |
| 복잡한 기능·다중 파일 리팩터링·실제 실행/테스트 | Codex | 기능 브랜치/PR |
| 자동 검증·배포 | GitHub Actions (**구축 예정**) | Workflow run |
| 서버 응급 점검/관리 | 별도 인증된 SSH 관리자 | 운영 로그/Runbook |

이는 권장 분담이며 둘 중 어느 쪽에서도 가능한 작업은 실제 연결·권한·사용량 범위에서 수행할 수 있다. **ChatGPT와 Codex 간 실시간 대화 동기화는 없다.**

## 표준 흐름
1. **계획**: 작업 Issue에 목적·수용조건·검증 방법을 적는다. 기존 Issue가 있으면 재사용한다.
2. **동기화**: 담당 AI는 최신 `test` 및 관련 파일, 열린 PR을 조회한다.
3. **분기**: `test`에서 `feature/chatgpt-...`, `feature/codex-...`, `fix/...` 등을 만든다. 동일 파일을 동시에 작업할 때는 담당자를 정한다.
4. **수정**: 필요한 최소 코드만 변경한다. 새 AI로 인계한다면 PR 본문에 변경 파일, 주의 사항, 미완료 작업을 명시한다.
5. **검증**: 가능한 테스트와 모바일 수동 테스트를 수행하고, 실제로 수행한 결과만 기록한다.
6. **통합**: 기능 브랜치 → `test` PR. 충돌 확인, 리뷰 및 테스트 후 통합한다.
7. **출시**: 사용자 확인 후 `test` → `main` PR. AWS 구축 전에는 기존 GitHub Pages가 운영 기준이다.
8. **운영 배포**: 자동 배포 환경이 준비된 뒤 별도 배포 승인/요청으로 실행한다. 단순 GitHub push는 운영 배포 승인으로 보지 않는다.

## 작업 인수인계 표준
- 목적: Issue 번호, 기대 동작 및 완료 조건
- 기반: `test`의 기준 커밋 SHA 및 현재 작업 브랜치
- 변경: 파일 목록과 핵심 설계 결정
- 검증: 실행 명령, 성공/실패, 미실행 사항, 모바일 확인 결과
- 후속: 남은 작업, 배포 영향, 새로운 환경 변수/비밀값이 필요한지 여부
- 배포: 배포 대상과 승인 여부(기본값: 미승인)

## 충돌·안전 수칙
- 오래된 소스를 전체 파일로 덮어쓰지 않는다. 수정 직전 최신 blob SHA/commit SHA 확인을 권장한다.
- `main`과 `test`의 커밋 그래프가 분기되어 있을 수 있다. 병합 방향을 검토하고 강제 덮어쓰기를 하지 않는다.
- 같은 기능을 두 AI에게 동시에 맡길 때는 각각의 소유 파일 또는 분리 가능한 작업 영역을 지정한다.
- 작업 내역·이슈·문서가 일치하지 않으면 **실제 코드 및 실행 확인 결과**를 우선으로 판단하고 기록을 보정한다.

## 아이폰에서 요청하는 예시
- ChatGPT: "GitHub 최신 test를 확인하고 Issue #9의 기록 화면 요구사항을 정리해 줘."
- ChatGPT: "관련 파일만 수정하는 브랜치를 만들고 test 대상 PR을 올려줘. main에는 반영하지 마."
- Codex: "PR의 변경 사항을 기준으로 모바일 UI 관련 버그를 수정하고 가능한 테스트를 실행해 줘."
- 추후 배포: "승인된 main 커밋 SHA를 AWS 운영 서버에 배포하고 상태 점검 결과를 알려줘." (**배포 워크플로와 권한 구성이 먼저 필요**)

## 사용량 관리
- 코드·이슈 설명, 구조 설계, 작은 패치, PR 검토는 ChatGPT를 우선 고려한다.
- 다중 파일 변경·실행 기반 검증·복잡한 리팩터링은 Codex를 우선 고려한다.
- 각 제품의 사용량/연동 제한은 별도로 확인한다. 특정 대화 방식이 Codex 할당량을 반드시 절약한다고 가정하지 않는다.
